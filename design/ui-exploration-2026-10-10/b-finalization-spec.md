## 二、后续实现约束

以下是将四张静态稿应用到现有产品时需要遵守的边界。本轮没有实施这些改动，也不追加新设计画面。

### 1. 只读与聊天绑定

- 仓库来自当前聊天入口 cwd 的 context 解析结果；路径是展示值，不提供编辑、历史仓库选择或手动切换入口。
- “分支”导航只承接现有本地分支、远程分支、标签的提交筛选；它不得新增 branch 管理页或 checkout 行为。
- 工作树卡片和概览只读；其他工作树即使出现，也不改变面板当前的 `repo.root`。
- 保留已有的历史、工作区改动、工作树三个内容视图，以及已有文件选择、统一差异、复制 SHA、资源读取和本机刷新能力；不得把静态图标当成新增业务的授权。
- 不增加暂存、提交、冲突解决、编辑文件、fetch、pull、push、审阅批准、评论、工作树创建或删除操作。

### 2. 数据与统计

- 14 个文件、+79 / −38、+6 / −2、比例图形、父提交、编码、换行与文件类型都可以作为真实快照画在设计稿中；后续实现须由既有资源或其已有真实数据提供，不得把稿中常量写进运行时页面。
- 当前组件明确使用提交文件集合与 patch；不能仅凭设计稿就断言现有 API 已提供所有增删统计和文件元信息。实现前需要核对可用字段，缺失时收敛展示，不能伪造值。
- 工作区总数表示不同文件数。同一文件可能同时拥有已暂存和未暂存内容，三组数量不能简单相加当作文件总数。
- 后续应将未跟踪显示符号与现有状态枚举明确映射。当前代码使用 `?` 表示未跟踪、U 表示冲突；不可直接照搬画面 U 后丢失两者区别。
- 当前工作树身份由实际路径与当前 root 匹配，不能仅凭分支相同识别。没有其他工作树时沿用本稿的真实空状态。

### 3. 控件与状态

桌面开关画为开启，是便于查看控件的设计展示状态。现有 App 的自动刷新默认为关闭；本轮没有授权修改默认行为。后续仍遵守 15 秒、页面可见且未在读取时刷新、无仓库时禁用的既有规则。刷新只重读当前聊天本机目录，不联网 fetch。

搜索仍只针对已加载提交说明、作者与哈希，保留关系图上下文；不能变成全局文件搜索。分支入口、菜单、前后文件按钮和收起图标是画面中的控件表达，不证明相应事件、键盘行为或状态切换已经实现。

静态稿中的分组、文件夹和卡片组织可作为现有数据的界面呈现依据；不新增未支持的写操作。文件选择与引用筛选沿用既有数据及选择状态。统一视图文字不表示增加并排差异模式。

读取中、未绑定、无仓库、目录不可用、资源读取失败、无提交、无文本差异与截断提示沿用现有 `App.jsx` / `components.jsx` 状态语义。本轮未画这些状态，也未承诺补稿。读取失败时不得显示其他聊天或过期仓库为当前绑定。

### 4. 尺寸与交付边界

已确定的画面视口只有 1600 × 1000 桌面和 760 × 1000 窄面板。后续响应式实现以这两个结构为参考，但本轮没有定全断点规则；不要把前版 900 px 以下上下结构、640 px 手机两层返回或 800 px 稿当成已选方案。

静态 HTML 的固定视口和最小宽度用于高清排版，不等于可直接照搬到所有产品窗口。后续实现保持正文与代码 13–14 px 的阅读尺寸，完整关键路径可取得，行号和符号对应逻辑行，滚动留在各自内容区。

本文件以四份最终 HTML 为结构依据，列出对应四张 PNG，并已只读查看画面与当前 token / manifest；评审后的减法修订以当前 HTML 为准。没有新增画面，没有修改业务代码，没有生成图片，没有运行构建或测试；静态图和排版源不构成交互或异步读取验收。
